# Support

## Start here

1. Read the [documentation](https://www.trysynara.com/docs).
2. Search existing issues for the same behavior.
3. Check the troubleshooting and provider guides.
4. Reproduce the problem with the smallest useful example.

## Where to ask

- Use the **Bug report** issue form for broken behavior, crashes, regressions,
  or reliability problems.
- Use the **Feature request** issue form for a concrete product problem or
  improvement.
- Use the **Question** issue form for usage questions that are not bug reports.
- Use private reporting described in [SECURITY.md](SECURITY.md) for
  vulnerabilities or exposed credentials.

Please do not include API keys, access tokens, browser cookies, private source
code, or unredacted provider transcripts.

## What to include

Include the Synara version or commit, operating system, relevant provider and
model, reproduction steps, expected behavior, actual behavior, and the smallest
useful log excerpt.

Support is best-effort. Maintainers may ask for more information, redirect a
question to the documentation, or close reports that are duplicates,
unsupported, or missing the information needed to investigate.
